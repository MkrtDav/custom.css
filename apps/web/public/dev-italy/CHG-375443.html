Casino: free-play demo for slot games

How the free-play (demo) mode of slot games works on the Italian site and apps: launch without login or payment, identical to the real-money game, what a demo does and does not call, and the responsible-gaming strip.

Use with the task CHG-375443. The task is the requirement. This kit adds reference detail for building and testing it: ADM rules with their sources, flows, messages and checks. If the kit and the task differ, the task prevails; if the task and ADM's protocol differ, the protocol prevails.

1. At a glance

  • Same game. Demo and real money use the same game, the same maths version and the same rules: same RNG, game logic, RTP. Only the funds and the session handling differ.
  • No account, no ADM. A demo opens no user session and no ADM game session, and moves no money. Real play needs the login and the ADM session.
  • Launch from the lobby without login and without payment.
  • Scope. Slot games on the Italian site and apps. Other casino games are verified with each provider (see the task CHG-375443).
  • Provider confirmation. Each slot provider confirms in writing that its Italian demo uses the real-money RNG, maths and RTP; the same check applies to Digitain's own slots. The confirmations are kept for the technical report and the lab. A demo with boosted or different maths is a certification finding.
  • Responsible-gaming strip stays on demo pages as on the rest of the site.

What the platform builds

  • Demo entry from the lobby that works without a user session: no login prompt, no deposit prompt. A demo token or launch URL carries no account or player identifier.
  • Provider launch adapters for the integration patterns in use (native, launch parameter such as a fun mode, token API). The adapter never receives an account ID. A provider error shows a neutral message and never falls back to real money.
  • No money path: play credits only; the demo never calls the real wallet, PACG, PGDA or the bonus engine, and does not read the account bonus balance.
  • Same game configuration: demo and real launch use the same game ID and maths version; the maths version and configured RTP of both launch configurations are compared and a difference is flagged.
  • A confirmation register: per provider and game list, the document reference, date, maths version and signer, exportable for the technical report and the lab.
  • A policy setting: the game types that offer a demo are a per-market setting, so a change of scope needs no release.
  • Real money from demo: an explicit "Play for real" step with the login (if needed) and the normal session steps of CHG-375326; disabled while a spin is in progress.

2. Rules

  1. The scope of the demo is slot games, Digitain's own and third-party providers', on the Italian site and apps. CHG-375443
  2. The demo must not differ in any respect from the real-money version and behaves the same way in line with the game rules: same RNG, game logic and maths, same RTP, same rules. Technical rules 2024 Part 2 ch. 4; Guidelines 2.4.1.1
  3. Each slot demo can be launched from the lobby without opening a user session and without payment. Guidelines 2.4.1.1
  4. Game functions that need no money payment are available without the player's access to the gaming account. Technical rules 2024 Part 2 ch. 1; Guidelines 2.4.1
  5. Each slot provider confirms in writing that its Italian demo uses the real-money RNG, maths and RTP; the same check applies to Digitain's own slots. The confirmations are kept for the technical report and the lab.
  6. A demo is not an ADM game session: the PGDA game-play flows start from the opening of a game session and the purchase of participation rights with money, so a demo launch sends no PGDA message and no PACG movement. PGDA 5.4; Guidelines 2.4.1.1
  7. Real play and account functions need the login: access to the game functions is possible only after the player's authentication and the login cannot be bypassed. Guidelines 2.7.2, 2.7.2.1
  8. The site and the apps keep the ban on play by minors, the ADM and "gioco legale e responsabile" logos, risk information and help contacts, and the player-protection measures clearly visible. The responsible-gaming strip is therefore shown on demo pages too. Guidelines 2.7.3, 2.7.4
  9. Alerts run during the user session: spend threshold at most 100 euro per session, time threshold at most one hour. Time is connection time from login to disconnection on any device, so for a logged-in player it keeps counting during demo play; spend is played minus won and refunded, so demo adds zero. The rules are in CHG-375442. Guidelines 2.9.2, 2.9.2.1
  10. Retention: all information of the last six months is available in real time and accounting information of two years; after that it is kept at least five more years. The storage duties attach to gaming-account operations and to game sessions with participation rights, and a demo has neither. Guidelines 2.1.16, 2.1.16.1, 2.3.4.1
  11. A game application is disabled only after checking that no game session is open; removing it from the system is a change that needs a new verification request. Guidelines 2.4.8.1
  12. When a user session ends and interrupts a game activity, the interrupted activity is restored at the next login in the state it had when interrupted. Guidelines 2.1.15, 2.1.15.1
  13. The verification objective is written for each game application and checks that it can be used without a user session and without paying money, with the same RNG and game logic. The slots-only scope is a scope decision of the task. Guidelines 2.4.1.1

6. Screens

  • Lobby card: for a slot, a Demo button and a Real money button; Real money for a logged-out visitor leads to login. Non-slot games show no Demo button under the slots-only scope.
  • Demo game screen: the game with play credits, a clear free-play marking (text, not colour alone), the responsible-gaming strip, and the actions Play for real and Back to lobby. Out of credits: restart the demo credits.
  • Play for real: logged out, login first. Logged in, the normal amount choice of the real-money session. Not available while a round is in progress.
  • Errors: provider failure shows a neutral message and Back to lobby. Never a technical code and never a fall back to real money.
  • Accessibility: the marking is real text with a status role on load and stays visible during play; disabled buttons stay focusable with the reason in text; contrast 4.5:1 in light and dark; touch targets 44 px on mobile.
  • Responsible-gaming strip: at least the items ADM names as always visible on the site and apps: the ADM logo and the "gioco legale e responsabile" logo, the ban on play by minors, information on the risks of gambling with contacts for help, the player-protection measures and the link to the ADM site.
