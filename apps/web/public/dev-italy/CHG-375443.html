Casino: free-play demo for slot games

How the free-play (demo) mode of slot games works on the Italian site and apps: launch without login or payment, identical to the real-money game, and the responsible-gaming information.

Use with the task CHG-375443. The task is the requirement. This kit adds reference detail for building and testing it: ADM rules with their sources, flows, messages and checks. If the kit and the task differ, the task prevails; if the task and ADM's protocol differ, the protocol prevails.

At a glance

  • Same game. Demo and real money use the same game, the same maths version and the same rules: same RNG, game logic, RTP. Only the funds and the session handling differ.
  • No account, no ADM. A demo opens no user session and no ADM game session, and moves no money. Real play needs the login and the ADM session.
  • Launch from the lobby without login and without payment.
  • Scope. Slot games on the Italian site and apps. Other casino games are outside this kit.
  • Provider confirmation. Each slot provider confirms in writing that its Italian demo uses the real-money RNG, maths and RTP, and the same check applies to Digitain's own slots (a Digitain internal control, not an ADM rule). A demo with boosted or different maths would not meet the "no difference in any aspect" rule.
  • Responsible-gaming strip stays on demo pages as on the rest of the site.

Rules

  1. The scope of the demo is slot games, Digitain's own and third-party providers', on the Italian site and apps. CHG-375443
  2. The demo must not differ in any respect from the real-money version and behaves the same way in line with the game rules: same RNG, game logic and maths, same RTP, same rules. Technical rules 2024 Part 2 ch. 2; Guidelines 2.4.1.1
  3. Each slot demo can be launched from the lobby without opening a user session and without payment. Guidelines 2.4.1.1
  4. Game functions that need no money payment are available without the player's access to the gaming account. Technical rules 2024 Part 2 ch. 1; Guidelines 2.4.1
  5. A demo is not an ADM game session: the PGDA game-play flows start from the opening of a game session and the purchase of participation rights with money, so a demo launch sends no PGDA message and no PACG movement. PGDA 5.4; Guidelines 2.4.1.1
  6. Account management and real-money play need the login: access to the game functions is possible only after the player's authentication and the login cannot be bypassed. Guidelines 2.7.2, 2.7.2.1
  7. The site and the apps keep the ban on play by minors, the ADM and "gioco legale e responsabile" logos, risk information and help contacts, and the player-protection measures clearly visible. The responsible-gaming strip is therefore shown on demo pages too. Guidelines 2.7.3, 2.7.4
  8. Alerts run during the user session: spend threshold at most 100 euro per session, time threshold at most one hour. Time is connection time from login to disconnection on any device, so for a logged-in player it keeps counting during demo play; spend is played minus won and refunded, so demo adds zero (our arithmetic). The rules are in CHG-375442. Guidelines 2.9.2, 2.9.2.1
  9. Retention: all information of the last six months is available in real time and accounting information of two years; after that it is kept at least five more years. The storage duties attach to gaming-account operations and to game sessions with participation rights, and a demo has neither (our reading; the reconstruction of plays of the last six months does not exclude free play). Guidelines 2.1.16, 2.1.16.1, 2.3.4.1
  10. A game application is disabled only after checking that no game session is open; removing it from the system is a change that needs a new verification request. Guidelines 2.4.8.1
  11. When a user session ends and interrupts a game activity, the interrupted activity is restored at the next login in the state it had when interrupted. Guidelines 2.1.15, 2.1.15.1
  12. The verification objective is written for each game application and checks that it can be used without a user session and without paying money, with the same RNG and game logic. The slots-only scope is a scope decision of the task. Guidelines 2.4.1.1

The PGDA protocol holds no free-play clause because it is a message protocol for participation with money. The free-play clause sits in the technical rules and in the verification guidelines.
